# Hexbot — ربات تلگرام با Ollama محلی

ربات متنی با Python 3.10 یا جدیدتر و Ollama محلی. در حالت منشی، حافظه، پروفایل، درخواست‌ها و پیش‌نویس‌ها در PostgreSQL یا SQLite ذخیره می‌شوند. تلگرام به اینترنت نیاز دارد؛ پردازش مدل روی کامپیوتر خودتان انجام می‌شود.

قالب‌های رایج خروجی مدل، شامل بک‌تیک تکی برای کد، بلوک کد سه‌بک‌تیکی، بولد، ایتالیک و خط‌خورده، به قالب‌بندی تلگرام تبدیل می‌شوند. این قابلیت در حالت ربات معمولی و منشی فعال است؛ پیام‌های بلند با حفظ قالب‌بندی تقسیم می‌شوند. این تبدیل، پیاده‌سازی کامل Markdown نیست؛ علامت نقل‌قول معمولی بخشی از متن باقی می‌ماند.

پاسخ‌های مدل به پیام اصلی مخاطب ریپلای می‌شوند، حتی اگر به چند پیام تقسیم شوند. دستور مدل، پاراگراف‌های کوتاه، فاصله بین موضوع‌ها و فهرست برای چند مورد مستقل را درخواست می‌کند؛ رعایت دقیق این سبک به مدل بستگی دارد. تقسیم پیام‌های بلند تا جای ممکن روی مرز پاراگراف یا خط انجام می‌شود.

## راه‌اندازی

1. [Ollama](https://ollama.com/download) و Python 3.10+ را نصب کنید.
2. یک مدل دانلود کنید؛ نام دقیق همان مدل را در تنظیمات قرار دهید:
   ```sh
   ollama pull qwen2.5:3b
   ```
3. Ollama باید اجرا باشد. اگر برنامهٔ Ollama از قبل اجرا نیست:
   ```sh
   ollama serve
   ```
4. در تلگرام از [BotFather](https://t.me/BotFather) با `/newbot` توکن بگیرید.
5. پروژه را دریافت کنید:
   ```sh
   git clone https://github.com/Tahanoa/hexbot.git
   cd hexbot
   ```
6. `.env.example` را با نام `.env` کپی کنید:
   - ویندوز PowerShell: `Copy-Item .env.example .env`
   - لینوکس / macOS: `cp .env.example .env`
7. وابستگی‌ها را نصب کنید، در `.env` مقدار `TELEGRAM_BOT_TOKEN` را وارد کنید و سپس اجرا کنید:
   ```sh
   python -m pip install -r requirements.txt
   python bot.py
   ```
   در برخی سیستم‌ها دستور `python3 bot.py` است. ربات را در تلگرام باز کنید و `/start` بفرستید.

## تنظیمات

| متغیر | پیش‌فرض | کاربرد |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | الزامی | توکن BotFather |
| `OLLAMA_BASE_URL` | `http://127.0.0.1:11434` | آدرس Ollama؛ ربات و Ollama را روی یک سیستم اجرا کنید |
| `OLLAMA_MODEL` | `qwen2.5:3b` | نام مدل نصب‌شده؛ با `ollama list` ببینید |
| `OLLAMA_TIMEOUT` | `180` | حداکثر زمان انتظار پاسخ، به ثانیه |
| `OLLAMA_NUM_CTX` | `8192` | ظرفیت توکن برای پرامپت، تاریخچه و پاسخ؛ مقدار بیشتر حافظه بیشتری مصرف می‌کند |
| `HISTORY_TURNS` | `8` | تعداد جفت پیام و پاسخ در حافظهٔ هر گفتگو |
| `MAX_CHATS` | `100` | سقف گفتگوهای نگهداری‌شده در حافظه |
| `MAX_CONCURRENT_CHATS` | `2` | سقف گفتگوهای هم‌زمان؛ برای سیستم ضعیف `1` بگذارید |
| `SYSTEM_PROMPT` | پاسخ به زبان کاربر | دستور ثابت برای رفتار مدل |
| `TELEGRAM_PROXY_URL` | خالی | پراکسی HTTP(S) برای تلگرام؛ خالی یعنی استفاده از تنظیمات سیستم، مثلاً `http://127.0.0.1:8080` |

متغیرهای محیطی سیستم بر `.env` اولویت دارند. فایل `.env` کنار `bot.py` خوانده می‌شود. توکن را داخل کد یا Git قرار ندهید. اتصال Ollama از پراکسی عبور نمی‌کند؛ پراکسی فقط برای تلگرام است. وقتی `TELEGRAM_PROXY_URL` خالی باشد، پراکسی محیط یا تنظیمات پراکسی ویندوز به‌صورت خودکار استفاده می‌شود. پراکسی سفارشی غیرخالی بر تنظیمات خودکار اولویت دارد. تنظیم قدیمی `ALLOWED_USER_IDS` دیگر خوانده نمی‌شود؛ همهٔ کاربران مجاز در تلگرام پاسخ می‌گیرند.

## دستورات و رفتار

- `/start` و `/help`: راهنما
- `/reset`: پاک‌کردن حافظهٔ همان گفتگو
- `/model`: نمایش نام مدل
- `/whoami`: نمایش شناسهٔ عددی خودتان
- فقط چت خصوصی و پیام متنی پشتیبانی می‌شود.
- در حالت ربات معمولی، حافظه موقت است؛ در حالت منشی، تاریخچهٔ اخیر و خلاصه در دیتابیس می‌مانند.
- در حالت منشی، پیام‌های پشت‌سرهم همان گفتگو جمع می‌شوند؛ ظرفیت صف هر گفتگو ۲۰ پیام است. در صورت پر بودن ظرفیت، درخواست ارسال مجدد داده می‌شود.
- پاسخ‌های بلند با حفظ قالب‌بندی به چند پیام تقسیم می‌شوند.
- از long polling استفاده می‌شود؛ دامنه، پورت ورودی و webhook لازم نیست. فقط یک نسخه از ربات را اجرا کنید.
- توقف با `Ctrl+C`؛ خروج ممکن است تا پایان درخواست‌های جاری طول بکشد.
- این نسخه صف پایدار ندارد؛ قطع ناگهانی برنامه ممکن است پاسخ پیام در حال پردازش را از دست بدهد. پیام را دوباره بفرستید.

## رفع مشکل

- **Ollama پاسخ نمی‌دهد:** اجرای Ollama، نام مدل و آدرس را بررسی کنید. مدل را با `ollama list` ببینید و برای پاسخ کند، `OLLAMA_TIMEOUT` را افزایش دهید.
- **خطای `exceed_context_size_error`:** درخواست از ظرفیت مدل بزرگ‌تر است. تنظیم `OLLAMA_NUM_CTX=8192` در `.env` برای پروفایل منشی حدود ۵۰۰۰ توکن مناسب است. برای گفتگوهای طولانی، تاریخچه را با `HISTORY_TURNS=2` کم کنید یا ظرفیت را با توجه به حافظه و محدودیت مدل افزایش دهید. بعد از تغییر، ربات را دوباره اجرا کنید.
- **مرورگر تلگرام را باز می‌کند اما ربات متصل نمی‌شود:** دسترسی به `telegram.org` الزاماً دسترسی به `api.telegram.org` را تأیید نمی‌کند. نسخه جدید از پراکسی سیستم استفاده می‌کند. با `TELEGRAM_PROXY_URL=` امتحان کنید و در صورت باقی‌ماندن خطا، علت جدید مثل `DNS resolution failed`، `Connection timed out` یا `TLS certificate verification failed` را بررسی کنید. خطای گواهی را با غیرفعال‌کردن اعتبارسنجی TLS حل نکنید.
- **تلگرام متصل نمی‌شود:** توکن، دسترسی اینترنت و در صورت نیاز `TELEGRAM_PROXY_URL` را بررسی کنید. پراکسی SOCKS در این نسخه پشتیبانی نمی‌شود.
- **خطای 409:** نسخهٔ دیگر ربات را متوقف کنید. اگر webhook فعال است، آن را با روش `deleteWebhook` در Bot API حذف کنید؛ برنامه خودکار webhook موجود را حذف نمی‌کند.
- **ربات روی سرور و Ollama روی کامپیوتر است:** `127.0.0.1` به همان دستگاه اجرای ربات اشاره دارد. ساده‌ترین اجرا، نصب هر دو روی کامپیوتر خودتان است؛ برای دستگاه جدا از شبکهٔ خصوصی امن استفاده کنید.

تست‌ها از تلگرام و Ollama شبیه‌سازی‌شده استفاده می‌کنند و توکن یا مدل واقعی لازم ندارند.

## منشی حساب شخصی تلگرام (Telegram Business)

این حالت به پیام‌های حساب شخصی شما در گفتگوهای مجاز پاسخ می‌دهد. پاسخ‌دادن از اتصال رسمی business bot استفاده می‌کند و لاگین حساب شخصی، API_ID یا API_HASH نمی‌خواهد. فقط قابلیت اختیاری خواندن تاریخچهٔ قدیمی به ورود حساب شخصی نیاز دارد. Ollama روی سیستم خودتان می‌ماند. جای گزینهٔ اتصال ربات ممکن است در نسخه‌های مختلف اپ، Chatbots / Chat Automation / Telegram Business نام داشته باشد.

### فعال‌سازی

1. نسخهٔ جدید کد را با `git pull` دریافت کنید و برنامهٔ قبلی را متوقف کنید.
2. قبل از فعال‌کردن این حالت، در چت خود ربات `/whoami` بفرستید و شناسهٔ عددی‌تان را بردارید.
3. `secretary.example.json` را با نام `secretary.json` کپی کنید و اطلاعات واقعی خودتان، لحن، حقایق و پاسخ سؤال‌های متداول را داخل آن بنویسید. فایل خصوصی است و در Git قرار نمی‌گیرد. اطلاعات این فایل ممکن است در پاسخ به مراجعه‌کننده استفاده شود؛ فقط اطلاعاتی را بنویسید که اجازه بیان آن‌ها را می‌دهید.
4. این موارد را به `.env` اضافه کنید؛ تنظیمات توکن، مدل و پراکسی قبلی باقی می‌مانند:
   ```env
   BUSINESS_MODE=true
   OWNER_USER_ID=شناسه_عددی_خودتان
   SECRETARY_PROFILE=secretary.json
   SECRETARY_DATABASE=data/secretary.sqlite3
   ```
5. در BotFather، از `/mybots` ربات خودتان را انتخاب کنید و در Bot Settings گزینهٔ Business Mode / Secretary Mode را فعال کنید.
6. در تنظیمات حساب تلگرام، بخش Chatbots / Chat Automation / Telegram Business → Chatbots، ربات خودتان را متصل کنید. گفتگوهای مجاز را انتخاب کنید و دسترسی پاسخ‌دادن به پیام‌ها را بدهید.
7. `python bot.py` را اجرا کنید. با یک حساب دیگر به حساب شخصی خودتان پیام بدهید. ابتدا با یک گفتگوی مشخص آزمایش کنید.

منشی مستقیم جواب می‌دهد و پایین هر پاسخ، امضای «توسط دستیار شخصی» با لینک قابل کلیک به خود ربات می‌گذارد. نام کاربری از `getMe` گرفته می‌شود. پیام انتظار این امضا را ندارد. معرفی اداری درخواست نمی‌شود؛ اگر مخاطب درباره هویت پرسید، پاسخ باید صادقانه باشد. تغییر پروفایل با `/profile` بدون ری‌استارت اعمال می‌شود. تأیید نوبت یا انجام کار بیرونی پیاده‌سازی نشده است.

### کنترل منشی

این دستورات را **از حساب خودتان به چت ربات** بفرستید؛ در گفتگو با مراجعه‌کننده نفرستید:

| دستور | رفتار |
|---|---|
| `/secretary on` | روشن‌کردن پاسخ‌گویی خودکار |
| `/secretary off` | خاموش‌کردن پاسخ‌گویی خودکار |
| `/inbox` | نمایش ده درخواست ثبت‌شدهٔ آخر و شناسه گفتگو |
| `/chats` | شناسه بیست گفتگوی ثبت‌شدهٔ آخر؛ بدون نیاز به `/human` |
| `/status` | وضعیت کلی منشی، مدل، ظرفیت توکن و آخرین وضعیت اتصال مشاهده‌شده در اجرای فعلی |
| `/clear_inbox` | پاک‌کردن درخواست‌های ثبت‌شده |
| `/waiting` | راهنمای انتخاب ایموجی انتظار؛ `/waiting default` برای ساعت شنی معمولی |
| `/emoji` | انتخاب ایموجی متحرک ابتدای پاسخ‌ها؛ `/emoji off` برای خاموش‌کردن |
| `/approval on` / `/approval off` | فعال/غیرفعال‌کردن پیش‌فرض تأیید دستی پاسخ‌ها |
| `/drafts` | نمایش پیش‌نویس‌های منتظر تأیید |
| `/approve ID` | ارسال یک پیش‌نویس؛ دوباره قابل تأیید نیست |
| `/edit ID متن جدید` | ویرایش پیش‌نویس؛ ارسال فقط پس از `/approve` |
| `/reject ID` | رد پیش‌نویس بدون ارسال |
| `/memory CHAT_ID` | نمایش خلاصهٔ حافظهٔ گفتگو |
| `/remember CHAT_ID` | ساخت خلاصه از حداکثر ۳۰۰ پیام اخیر |
| `/forget CHAT_ID` | پاک‌کردن تاریخچه، خلاصه، آرشیو و پیش‌نویس‌های گفتگو |
| `/profile show` | نمایش پروفایل فعال |
| `/profile reload` | بارگذاری دوباره از `secretary.json` |
| `/profile set tone لحن صمیمی و کوتاه` | تغییر یک فیلد و ذخیره در دیتابیس |

برای پیدا کردن ایموجی متحرک از پک بدون ارسال دستی آن، در چت خصوصی ربات از حساب مالک بفرستید:

```text
/emoji https://t.me/addemoji/YellowEmojis_by_TgEmodziBot ✨
```

ربات شناسه گزینه‌های متحرکی را که با ✨ مرتبط‌اند نشان می‌دهد. برای انتخاب، یکی از دستورهای `/emoji شناسه` نمایش‌داده‌شده را بفرستید. حذف ایموجی معمولی انتهای دستور، تا ۲۰ گزینه متحرک اول پک را نمایش می‌دهد. شناسه با `getCustomEmojiStickers` بررسی و در دیتابیس ذخیره می‌شود؛ فقط ایموجی متحرک یا ویدیویی پذیرفته می‌شود. یک ایموجی در ابتدای اولین بخش پاسخ مدل اضافه می‌شود؛ ایموجی انتظار جداگانه تنظیم می‌شود. دریافت شناسه مجوز ارسال پریمیوم نمی‌دهد: شرایط Bot API تلگرام همچنان برقرار است. اگر ارسال با ایموجی سفارشی خطای ۴۰۰ بدهد، همان پاسخ با ایموجی معمولی و با حفظ ریپلای و قالب‌بندی یک بار دوباره ارسال می‌شود. خطاهای شبکه یا سایر خطاها چنین تکراری ندارند.

برای پیام انتظار، در تنظیمات اتصال ربات به حساب تلگرام، مجوز حذف پیام‌های ارسالی خود ربات را فعال کنید. پیش از تولید مدل (حتی هنگام انتظار در صف)، پیام بی‌صدای `⏳` ارسال می‌شود و پس از پاسخ، خطا یا لغو پردازش حذف می‌شود. اگر مجوز حذف وجود نداشته باشد، پیام انتظار ارسال نمی‌شود تا پیام دائمی اضافه باقی نماند. خطای ارسال یا حذف ایموجی، پاسخ اصلی را متوقف نمی‌کند.

صاحب حساب می‌تواند فقط یک ایموجی سفارشی پریمیوم در چت مستقیم ربات بفرستد تا به‌عنوان ایموجی انتظار ذخیره شود؛ برای حرکت، یک ایموجی متحرک انتخاب کنید. شناسه و ایموجی در SQLite باقی می‌مانند. تلگرام استفاده از ایموجی سفارشی توسط ربات‌ها را محدود می‌کند؛ اگر ارسال آن با خطای ۴۰۰ رد شود، ساعت شنی معمولی جایگزین می‌شود. حذف این پیام با `deleteBusinessMessages` انجام می‌شود و اعلان حذف آن، گفتگوهای بعدی را لغو نمی‌کند. اگر اتصال حین حذف قطع شود، پیام ممکن است باقی بماند و علت در لاگ ثبت می‌شود.

`/secretary on` منشی را برای همه روشن می‌کند و `/secretary off` برای همه خاموش می‌کند. دستورات جدول زیر را **از حساب شخصی خودتان در پیوی شخص مقابل** به‌صورت پیام مستقل بفرستید. ربات نتیجه را در چت خصوصی خودش به شما گزارش می‌کند و تلاش می‌کند همان پیام دستور را حذف کند. برای حذف پیام مالک، مجوز **حذف همه پیام‌ها** (`can_delete_all_messages`) در اتصال ربات لازم است؛ مجوز حذف پیام‌های خود ربات کافی نیست. ابتدا از حساب مالک در چت ربات `/start` بفرستید تا اعلان‌ها قابل ارسال باشند. در صورت نبود مجوز یا خطای شبکه، دستور اجرا می‌شود اما پیام ممکن است باقی بماند؛ نتیجهٔ حذف جداگانه گزارش می‌شود.

| دستور در پیوی شخص | کاربرد |
|---|---|
| `/stop` | توقف دستی پاسخ‌گویی همین گفتگو |
| `/resume` | برداشتن توقف دستی همین گفتگو |
| `/remember` | خواندن حداکثر ۳۰۰ پیام اخیر و ساخت حافظهٔ کوتاه؛ نتیجه بعداً در ربات اعلام می‌شود |
| `/forget` | پاک‌کردن حافظه، آرشیو و پیش‌نویس‌های همین گفتگو |
| `/review on` / `/review off` | فعال/غیرفعال‌کردن تأیید دستی فقط برای همین گفتگو |

پیام مخاطب، دستور فورواردشده، پاسخ دستی معمولی، `/human` و تصمیم مدل توقف دائمی ایجاد نمی‌کنند. تنظیم `/review` هر گفتگو بر پیش‌فرض `/approval` اولویت دارد.

توقف دستی با راه‌اندازی دوباره، تغییر شناسه اتصال و خاموش/روشن‌کردن کلی منشی حفظ می‌شود؛ در `/chats` کنار شناسه با «توقف دستی» نمایش داده می‌شود. فقط `/resume` مالک آن را برمی‌دارد؛ اگر منشی کلی خاموش باشد، ادامه پاسخ‌گویی علاوه بر این به `/secretary on` نیاز دارد. توقف و ادامه، پاسخ‌های قدیمی در صف یا در حال تولید را لغو می‌کنند؛ ارسال تلگرامی که قبلاً شروع شده قابل پس‌گرفتن نیست. پیام انتظار در پایان پردازش لغوشده پاک می‌شود. توقف‌های خودکار نسخه‌های قدیمی همچنان هنگام مهاجرت حذف می‌شوند و به توقف دستی تبدیل نمی‌شوند.

مراجعه‌کننده می‌تواند `/human متن درخواست` بفرستد؛ درخواست ذخیره می‌شود، رسید دریافت می‌کند و اعلان به مالک می‌رسد. مدل نیز برای قیمت، قول، زمان‌بندی یا اطلاعات اختصاصی نامشخص، ارجاع به مالک را درخواست می‌کند؛ برنامه درخواست را ثبت و به شما اطلاع می‌دهد. این تشخیص به کیفیت مدل بستگی دارد و تضمین بی‌خطایی نیست. ارجاع، پاسخ‌گویی گفتگو را متوقف نمی‌کند. درخواست‌ها با `/inbox` قابل بررسی‌اند.

حافظهٔ اخیر گفتگو، خلاصه، آرشیو پیام‌های متنی دریافت‌شده، پاسخ‌ها، تنظیمات و پیش‌نویس‌ها پس از ری‌استارت باقی می‌مانند. حافظه بر اساس شناسهٔ مخاطب است و با تغییر شناسهٔ اتصال از بین نمی‌رود. `/forget` حافظه و آرشیو فعال را پاک می‌کند؛ درخواست‌های `/inbox` و نسخه‌های پشتیبان دیتابیس جدا هستند. در حالت تأیید، پاسخ تا `/approve` ارسال نمی‌شود و پیش‌نویس تازه جای قبلی همان گفتگو را می‌گیرد. توقف دستی و تغییر پروفایل، پیش‌نویس‌های قدیمی را لغو می‌کنند. در ارسال ناموفق یا ناقص، تکرار خودکار انجام نمی‌شود؛ گفتگو را بررسی کنید.

تغییرات `/profile set` در دیتابیس ذخیره و فوراً اعمال می‌شوند؛ فایل JSON تغییر نمی‌کند. `/profile reload` تغییرات دیتابیس را با محتوای فایل جایگزین می‌کند. مسیر تو‌در‌تو مثل `/profile set facts.city تهران` و مقدار JSON مثل آرایه نیز پشتیبانی می‌شود.

### PostgreSQL و انتقال اطلاعات قبلی

PostgreSQL را روی سیستم نصب و سرویس آن را روشن کنید. در pgAdmin یا `psql`، با حساب مدیر، هر دستور زیر را جداگانه اجرا کنید و رمز نمونه را عوض کنید:

```sql
CREATE USER hexbot WITH PASSWORD 'YOUR_PASSWORD';
CREATE DATABASE hexbot OWNER hexbot;
```

در `.env` تنظیم کنید:

```env
DATABASE_URL=postgresql://hexbot:YOUR_PASSWORD@127.0.0.1:5432/hexbot
MESSAGE_BATCH_SECONDS=3
```

کاراکترهای ویژهٔ رمز در URL باید percent-encode شوند. جدول‌ها داخل schema اختصاصی `hexbot` خودکار ساخته می‌شوند؛ حساب دیتابیس باید مجوز ساخت schema و جدول داشته باشد. اگر آدرس PostgreSQL تنظیم شده ولی اتصال ناموفق باشد، برنامه خطا می‌دهد و مخفیانه به SQLite برنمی‌گردد. خالی‌گذاشتن `DATABASE_URL` همان دیتابیس SQLite قبلی را نگه می‌دارد.

برای انتقال تنظیمات، درخواست‌ها و حافظهٔ موجود از SQLite، ابتدا ربات را متوقف کنید؛ سپس در Git Bash ویندوز:

```sh
cd /c/Users/ok/PycharmProjects/hexbot
git -c http.version=HTTP/1.1 pull origin main
./.venv/Scripts/python.exe -m pip install -r requirements.txt
./.venv/Scripts/python.exe migrate_postgres.py
./.venv/Scripts/python.exe bot.py
```

مهاجرت از مسیر `SECRETARY_DATABASE` به `DATABASE_URL` است؛ فایل قبلی حذف نمی‌شود و رکورد موجود مقصد بازنویسی نمی‌شود. مهاجرت را پیش از شروع استفاده از دیتابیس جدید انجام دهید. تنظیم `MESSAGE_BATCH_SECONDS` بین ۰ تا ۱۰ ثانیه است؛ صفر جمع‌کردن پیام‌ها را غیرفعال می‌کند. ربات پس از آخرین پیام چند ثانیه صبر می‌کند، با سقف ۱۰ ثانیه انتظار برای هر دسته، و پاسخ را به آخرین پیام دسته ریپلای می‌کند.

### خواندن ۳۰۰ پیام قبلی

Bot API امکان خواندن تاریخچهٔ قدیمی چت خصوصی را ندارد. بدون اتصال حساب، `/remember` فقط حداکثر ۳۰۰ پیام ذخیره‌شده توسط ربات را بررسی می‌کند و منبع و تعداد واقعی را گزارش می‌دهد. برای تاریخچهٔ واقعی، اتصال اختیاری MTProto با حساب **خود مالک** لازم است:

1. در [my.telegram.org](https://my.telegram.org) بخش API development tools، `api_id` و `api_hash` بگیرید.
2. فقط در `.env` محلی تنظیم کنید:

   ```env
   TELEGRAM_API_ID=YOUR_API_ID
   TELEGRAM_API_HASH=YOUR_API_HASH
   TELEGRAM_USER_SESSION=data/history-account
   HISTORY_PROXY_URL=
   ```

3. در Git Bash، ورود را یک‌بار روی کامپیوتر خودتان انجام دهید:

   ```sh
   ./.venv/Scripts/python.exe -m pip install -r requirements-history.txt
   ./.venv/Scripts/python.exe history_login.py
   ```

4. شماره، کد ورود و در صورت فعال‌بودن، رمز دومرحله‌ای را فقط در همان ترمینال وارد کنید. ربات را دوباره اجرا کنید و از حساب مالک در پیوی شخص `/remember` بفرستید.

حساب واردشده باید همان `OWNER_USER_ID` باشد. اتصال تاریخچه فقط چت خصوصی درخواست‌شده را از فهرست گفتگوهای مالک می‌خواند؛ پیام ارسال یا حذف نمی‌کند. حذف دستور همچنان با Bot API انجام می‌شود. اگر MTProto نیاز به پراکسی دارد، جداگانه `HISTORY_PROXY_URL=socks5://127.0.0.1:1080` یا پراکسی HTTP مناسب را تنظیم کنید؛ پراکسی Bot API خودکار به این اتصال منتقل نمی‌شود.

تا ۳۰۰ پیام خوانده می‌شود؛ اگر کمتر موجود باشد همان تعداد گزارش می‌شود. عکس، صدا و فایل به متن تبدیل نمی‌شوند و فقط با نشانگر پیام غیرمتنی در نظر گرفته می‌شوند. متن‌ها در دسته‌های کوچک خلاصه می‌شوند و حافظهٔ نهایی تا ۱۲۰۰ نویسه نگه داشته می‌شود؛ روی مدل کند، ساخت حافظه از ۳۰۰ پیام ممکن است چند دقیقه طول بکشد. نتیجه در چت ربات اعلام می‌شود و خطای ساخت، خلاصهٔ قبلی را عوض نمی‌کند. API hash، رمز، کد ورود و فایل `.session` را در Git یا پیام به دیگران قرار ندهید.

مراجع: [محدودیت getHistory برای حساب کاربری](https://core.telegram.org/method/messages.getHistory)، [ورود Telethon](https://docs.telethon.dev/en/stable/basic/signing-in.html).

### محدودیت‌های پردازش

پرامپت منشی گفتگوی روزمره و پرسش عمومی را می‌پذیرد؛ اطلاعات اختصاصی صاحب حساب از پروفایل گرفته می‌شوند. حافظهٔ مخاطب به‌عنوان دادهٔ گفتگو وارد پرامپت می‌شود و منبع تأییدشدهٔ اطلاعات مالک نیست. دستور معرفی‌نکردن بر درخواست معرفی در پروفایل یا تاریخچه اولویت دارد. این کنترل یک دستور به مدل است، نه تضمین کیفیت متن. امضای لینک‌دار را برنامه بیرون از متن مدل اضافه می‌کند؛ در تاریخچه مدل ذخیره نمی‌شود و در صورت رد ایموجی پریمیوم حفظ می‌شود. مدل به اینترنت دسترسی ندارد.

برای تشخیص کندی، لاگ `AI response ready` زمان رسیدن پاسخ مدل به برنامه را نشان می‌دهد. `Ollama timings` زمان بارگذاری، پردازش پرامپت و تولید را جدا می‌کند. سپس زمان بررسی مجوز تلگرام و `Telegram accepted reply` ثبت می‌شود؛ مورد آخر یعنی API تلگرام ارسال را پذیرفته، نه اینکه مخاطب پیام را خوانده است. زمان `wait before AI` شامل انتظار صف و بررسی اولیهٔ اتصال است. متن پیام، پروفایل و توکن در این لاگ‌ها چاپ نمی‌شوند.

- فقط پیام‌های جدید متنی در چت خصوصی مدیریت می‌شوند؛ تاریخچهٔ قبلی حساب و نسخهٔ ویرایش‌شدهٔ پیام‌ها خوانده نمی‌شوند.
- ربات فقط حساب `OWNER_USER_ID` و گفتگوهای مجاز در تنظیمات تلگرام را مدیریت می‌کند.
- طبق Bot API، حق پاسخ مربوط به گفتگوهایی است که در ۲۴ ساعت گذشته پیام ورودی داشته‌اند. اتصال و حق پاسخ قبل و بعد از تولید مدل بررسی می‌شود.
- تا ۲۰ پیام بعدی هر گفتگو هنگام تولید پاسخ در صف موقت قرار می‌گیرند؛ پر بودن صف یا ظرفیت گفتگوها با پیام «کمی بعد دوباره پیام بده» اعلام می‌شود. صف با خاموش‌شدن برنامه از دست می‌رود.
- در حالت منشی، چت مستقیم ربات برای کنترل صاحب حساب است. برای برگشت به ربات عادی، `BUSINESS_MODE=false` بگذارید و برنامه را دوباره اجرا کنید.
- پاسخ مدل تضمین‌شده نیست؛ جزئیات واقعی را در پروفایل وارد کنید و با چند پیام آزمایش کنید.

مرجع اتصال: [Connected business bots](https://core.telegram.org/api/bots/connected-business-bots)، [BusinessConnection و BusinessBotRights](https://core.telegram.org/bots/api#businessconnection).
